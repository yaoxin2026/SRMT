# MC-MT-SRMT benchmark

- Cases: spheroid, torus, gaussian_two
- Levels: 0.5
- Resolutions: 64^3, 128^3, 192^3, 256^3, 320^3, 384^3, 448^3, 512^3
- SRMT n_jobs worker counts: 1, 2, 4, 8
- SRMT construction modes: default
- "default": corrected subcell-dependent corner-to-center diagonals; "uniform": one translated orientation.
- Both modes use the same 27 interpolated nodes and 48 tetrahedra per selected parent cell.
- Three-state SRMT retains both coincident-face classes; duplicate winding follows the minimum parent-cell/local-tetrahedron owner.
- Parent selection is inclusive: min(corners) <= rho+epsilon and max(corners) >= rho-epsilon. Selected cells can generate no triangles.
- N_active is an SRMT candidate-cell diagnostic for all methods; MC and MT retain their own backend equality conventions.
- Topology comparisons report component/Euler invariants and edge incidence, not certified topology equivalence or genus.
- Strong-scaling speedup and serial/parallel checks use the P=1 baseline of the same construction mode.
- SRMT start method request: fork
- Independent repeats per configuration: 5
- Benchmark protocol: CPC-1.2-THREE-STATE-MEDIAN5
- Publication central statistic: median.
- Full post-extraction diagnostics (repeat 1 only): True
- Run-order policy: fixed deterministic method order in every repeat.
- The timed region contains only the extraction call; backend import, diagnostics, file I/O, and reference construction are excluded.
- No warm-up run, explicit garbage collection, inter-run sleep/cooldown, fitted correction, smoothing, outlier removal, or result imputation is used.
- Runtime and Peak RSS summaries report the median of exactly five successful raw repeats.
- Scalar-data range: [0,1]

## Level-set support and mesh diagnostics

`N_cell` and `N_active` use the same original-grid parent-cell definition for MC, MT, and SRMT. `N_tet` is not applicable to MC; for MT it is the number of explicit full-grid tetrahedra, whereas for SRMT it is the number of refined subtetrahedra processed only inside active parent cells.

## Geometry against the fixed original-grid trilinear field

These diagnostics are calculated on the raw repeat-1 mesh after extraction timing and RSS sampling. They use the same unchanged original nodal array for MC, MT, and SRMT; no analytic values are sampled at new nodes.

`R_h = max |f_h(x)-rho|` over all mesh vertices and all triangle centroids. It is a sampled scalar residual, not a whole-triangle error bound or a surface distance.
`Theta_h` is the area-weighted mean angle in degrees between a triangle normal and the physical gradient of `f_h` at its centroid. For this diagnostic, normals are oriented locally toward that gradient using `abs(dot)`; mesh winding is not assessed or modified. At interior grid planes the gradient is taken from the positive-index cell; at the upper domain boundary it uses the last cell.
`q05` is the unweighted fifth percentile of `4*sqrt(3)*area/sum(edge_length^2)`, using linear quantile interpolation. An equilateral triangle has quality 1; zero-area triangles have quality 0 and remain in the percentile.
A zero gradient on any positive-area triangle makes the full normal-angle mean unavailable (`--`/JSON null). `Normal area fraction` records the fraction of surface area with a defined normal-angle comparison. Zero-area faces carry zero weight.

For the scientific method comparison, compare MC, MT, and SRMT with `P=1`. The publication-default method comparison uses serial SRMT (`P=1`).

Extraction time is measured inside the worker with `time.perf_counter_ns()` immediately around the requested extraction call. Peak RSS is sampled externally by the parent process over the coordinator and all active descendants, so memory-profiling calls are not inserted into the timed method.

Peak RSS is the sum of per-process RSS values. It represents the complete process tree, but shared pages may be counted in more than one process. The raw rows record the aggregation rule and peak process count.

MC and MT use one benchmark process. For SRMT, P is the n_jobs extraction-worker count passed to the API; the benchmark worker remains the coordinator. Common native thread pools and VTK SMP are limited to one thread per process to avoid hidden nested parallelism.

The MT row uses the direct PyVista full-grid six-tetrahedron decomposition followed by direct contouring. No point welding, mesh cleaning, hole filling, smoothing, or topology repair is applied to the returned MT surface.

Compressed scalar fields and benchmark meshes are optional and disabled by default; Figures 03 and 04 generate their display meshes separately outside the performance benchmark when needed.
For gaussian_two, the two Gaussian terms are summed first, then divided by the fixed continuous maximum of the sum (approximately 1.01475932752). Every resolution samples the same continuously normalized field. The finest projected continuous-implicit reference mesh defines area and volume; the preceding refinement level supplies an explicit convergence-uncertainty estimate. No Richardson correction is applied to method results or reference values.
